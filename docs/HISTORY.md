## 5.12.1 (사용자 요청 2건)

- **설치가 막힐 때 경로 안내로 끝내지 않기.** 삼성 One UI 6+ 의 '보안 위험 자동 차단'(인증되지 않은 출처의 앱 설치 차단)이 켜져 있으면
  스토어 밖 앱은 설치·업데이트가 막히고 '이 출처 허용' 스위치도 회색으로 잠긴다. 그 차단 창은 시스템 창이라 손댈 수 없고,
  자동 차단 화면으로 가는 공개 주소도 없다 → 앱이 할 수 있는 최선:
  - 설치 화면을 연 기록(`updLaunchAt`·`updFromVer`)을 남기고, 돌아왔을 때 **버전이 그대로면** "설치가 막혔나요?" 창.
  - '이 출처 허용'을 켜러 갔다가 못 켜고 돌아와도 같은 창.
  - [보안 설정 열기] = `ACTION_SECURITY_SETTINGS`('보안 및 개인정보 보호', 자동 차단 바로 앞 화면) → 돌아오면 **설치를 자동으로 이어서**.
  - 설정 → '업데이트가 막힐 때'로 언제든 같은 안내. 브라우저로 받기는 새 버전 정보가 없어도 최신 릴리스 페이지로.
  - 폰에서 확인 전: 삼성 폰에서 이 화면이 실제로 '보안 및 개인정보 보호'로 열리는지.
- **설정 아이콘이 해(밝기)처럼 보임** → 톱니 모양(고리 + 네모 톱니 8개)으로 다시 그리고, 머리글 버튼에 '설정' 글자를 붙임.

## 5.12.0 — 알람 요건 (사용자와 함께 정함)

| 항목 | 결정 |
|------|------|
| 칸 나누기 | 반복 알람 2개(V1·V2) + 빠른 알람 1개(V3) — 그대로 |
| 다시 눕히기 | **알람마다 따로** (알람 1·2 편집 화면, 빠른 알람 칸). 5.11.1 의 공통 값(`alDown`)은 각 알람의 처음 값으로 옮김 |
| 상대 침대 알람 | **짝지은 폰에서도 보고 바꿈.** 설정은 주인 폰에 저장되고 주인 폰이 침대에 넣는다 → 주인 폰 앱이 켜져 있거나 '앱을 닫아도 대기'여야 바뀐다 |
| 빠른 알람 버튼 | 10분·30분·1시간·2시간 + 직접 + **마지막으로 직접 정한 시간**(`qaLastMin`, 폰마다) |

- `ApiServer` `/alarms`·`/alarmset` (도장 필수, 주인 폰에 있는 침대만, 알람 시험 전이면 거절). 빠른 알람은 폰 시계 차이 때문에 '남은 밀리초'로 주고받는다.
- 시험: `test/pairing` 에 [9] 16가지 — 받아오기·시험 전 거절·옛 값 옮김·저장·**주인 폰이 가짜 침대에 넣은 바이트까지**·잘못된 값·남의 열쇠. 총 51가지. `test/alarms` 17가지.

## 5.11.1 — 종료 시각의 뜻 (사용자 확인)

- 빠른 알람 시험: **올라가고 1분 뒤 다시 내려감** → 원래 앱의 시작~종료는 "시작에 올리고, 종료에 다시 눕힌다".
- "알람 뒤 다시 눕히기" 설정(침대별, 모든 알람 공통, `Alarms.down`): 안 함(기본) / 5분 / 10분 / 30분 / 1시간.
  '안 함'은 종료를 **다음 날 시작 1분 전**으로 둔다 — 그때 침대가 올라가 있지 않으면 아무 일도 없다(보통 자고 있어 이미 누워 있음). 빈 종료값은 기판이 어떻게 읽을지 몰라 쓰지 않았다.
- 빠른 알람을 끄는 시점도 다시 눕히기 뒤로 미룬다(`quickKeep`) — 먼저 끄면 눕히기가 취소될 수 있어서.

## 5.11.0 (사용자 요청)

- '몇 분에 걸쳐 올리기' 삭제: 침대는 시작 시각에 평소 속도로 올라갈 뿐이라 의미 없음. 시작~종료는 시험에서 동작한 1분으로 고정(`Alarms.WINDOW`).
  **종료 때 침대가 내려가는지는 아직 모름** — 내려간다면 WINDOW 를 크게 잡아야 한다.
- 빠른 알람: 10분·30분·1시간·2시간·직접(몇 시간 몇 분, 올라갈 시각을 바로 보여줌). 사용자 결정으로 **알람 3 자리(V3·V7)** 를 쓴다 → 반복 알람은 2개.
  침대 알람은 매주 반복이라, 그 날 그 요일 하루만 켜고 **울리고 2분 반 뒤** 앱이 끈다(그 전에 끄면 울리기 전에 꺼질 수 있어서).
  끄는 시점: 화면이 열려 있으면 그때, 아니면 다음에 침대가 접속하거나 앱을 열 때. 앱을 일주일 넘게 안 열면 한 번 더 울릴 수는 있다.
- `test/alarms`: 1분 고정 값, 빠른 알람 UTC 변환·요일, 남은 시간 글자 — 12가지.

## 5.10.1 — 알람 시험 중단 (사용자 신고)

- 증상: '알람 시험 시작' 몇 초 뒤 "시험 중에 침대 연결이 끊겼습니다".
- 원인(추정): 시험은 처음 연결 객체(`Dev`)를 붙잡고 "지금 연결이 그것과 다르면 끊김"으로 판정했다. 이 침대는 **움직이는 동안 응답을 안 하다가
  연결이 끊기고 스스로 다시 붙는** 것으로 보인다(평평하게 눕히는 명령 직후) → 새 연결 = 끊김으로 오판.
- 수정: 매 초 인증키로 지금 연결을 찾는다. 끊긴 동안은 기다리고(40초 넘으면 중단), 실패한 명령은 새 연결로 다시, 다시 붙으면 시험 알람도 다시 넣는다.
- 시험 끝(그만두기 포함)에 시험 알람을 **반드시 끈다** — 연결이 없으면 1분까지 재시도, 그래도 안 되면 `alDirty` 표시 → 다음 접속 때 `Alarms.push` 가 V5~V7 을 끈다.
  (안 끄면 매일 그 시각에 침대가 올라간다)

## 5.10.0 — 알람 되살리기 2단계

- 사용자 캡처: 침대가 접속하며 `vr 1 2 3 4`, `vr 5 6 7`, `vr 12`, `vr 51~55`, `vr 61` 을 달라고 함 → 원래 앱 화면과 맞춰 핀을 정함 (PROTOCOL 3장).
- `Alarms.java`: 침대별 알람 3개 저장, 침대가 붙을 때(`App` → `Alarms.onDevices`, 2초 뒤)와 바꿀 때 V1~V3·V5~V7·V12 를 넣는다.
  **시계 방식이 정해지기 전에는 아무것도 보내지 않는다** (엉뚱한 시각에 침대가 움직이지 않게).
- 메인 화면 '알람': 처음엔 "알람 시험 (5분)" — 평평하게 눕힌 뒤 두 가지 시계 가정으로 2분·4분 뒤 알람을 넣고 상체 값으로 판정, 끝나면 시험 알람을 끔.
  그다음부터 알람 1·2·3 (눌러서 시각·1/3/5/10분·요일, 켜짐/꺼짐 버튼), 알람 때 상체 높이 슬라이더.
- 원래 앱의 '시작~종료'는 '몇 분에 걸쳐 올릴까요'로 보여준다 (종료 = 시작 + 그 시간). 종료 때 침대가 무엇을 하는지는 아직 모른다.
- `test/alarms`: 값 형식·UTC 변환·요일 넘김 5가지. 점검(check.yml)에도 넣음.
- **폰에서 확인 전:** 시험 결과(local/utc/none), 실제 알람이 그 시각에 오르는지, 종료 시각 동작, 침대를 껐다 켠 뒤에도 알람이 다시 들어가는지.

## 5.9.3 — 알람 되살리기 1단계: 단서 모으기

- 사용자가 원래 앱 화면 캡처를 찾아옴 → 알람 3개(요일·시작·종료·켜기) + 알람 상체높이 + 타이머 + LED (docs/PROTOCOL.md "원래 앱 화면").
- 침대가 접속할 때 보내는 동기화 요청(HW_SYNC)의 **내용을 버리고 있었다** → 기록. `BedServer` 는 기록 한 줄만 바꿨다(응답·통신 규칙 그대로).
  뜻 모를 침대 메시지를 `App.bedHello()` 에 따로 모아 연결 기록 맨 위에 보여줌. "침대 다시 연결" = 침대 서버를 잠깐 껐다 켜서 재접속 유도.
- 다음 단계: 사용자 캡처에서 핀이 보이면 → 알람을 **침대 자체**로 설정 (폰 꺼져도 동작). 안 보이면 → 폰이 알람을 맡는 방식.

## 5.9.2 — 앱 안 업데이트 방식 교체 (사용자 신고: 또 "내려받는 중"만 지속)

- 5.6.1 에서 고친 뒤에도 사용자 폰에서 여전히 "내려받는 중"에서 끝나지 않았다. 폰 로그가 없어 **정확한 원인은 미확정**.
  코드상 이 글자는 '내려받기 + PackageInstaller 세션 설치'가 끝나야 바뀌었고, 그 사이에 멈추거나 Exception 이 아닌 오류로
  스레드가 죽으면 화면이 영원히 그대로였다(시간 제한도 없었다).
- 바꾼 것: PackageInstaller 세션·InstallReceiver 를 버리고, 브라우저·파일 앱이 쓰는 방식 — 앱이 받아서 `ApkProvider`(content://)로
  **안드로이드 기본 설치 화면**(ACTION_VIEW)을 연다. 이 폰에서 브라우저 설치는 늘 됐다. 매번 설치 화면에서 '업데이트'를 한 번 누른다
  (조용한 자동 설치는 포기 — 사용자가 이미 "묻고 설치"를 골랐다). `UPDATE_PACKAGES_WITHOUT_USER_ACTION` 권한 삭제.
- 받은 양을 "45KB / 94KB" 로 보여 준다. 20초 동안 한 바이트도 안 오면 멈춘 것으로 보고 실패. 어떤 오류든 이유 + **브라우저로 받기** 창.
  업데이트 묻는 창에도 '브라우저로 받기'.
- PC 에서 실제 `Updater.fetch` 로 깃허브 v5.9.1 을 받아 봄: 94,773바이트, 릴리스 파일과 SHA-256 동일, 진행 알림 6번.
- 5.9.1 이하에서 5.9.2 로는 앱 안 설치가 멈출 수 있으니 **브라우저로 한 번** 설치해야 한다.

## 5.9.1 — 짝짓기 재점검 (사용자 요청: "제대로 볼 것")

- **두 폰이 동시에 서로 짝짓기를 누르면** 각자 만든 열쇠를 맞바꿔 가져 짝이 영영 안 맞았다 → 요청하는 동안엔 남의 요청을 거절(`App.pairOut`), "한쪽에서만 눌러주세요" 안내.
- 상대 폰에 안 닿을 때도 1분을 기다렸다 → 닿는지는 4초, '허용' 기다림만 70초.
- `/state` 가 네트워크 재전송으로 두 번 오면 '재사용'으로 거절돼 상대 침대가 깜빡 사라질 수 있었다 → 재사용 검사는 바꾸는 요청(/cmd·/rename)에만.
- 이미 다른 짝이 있는 폰이 새로 요청하면 기존 짝이 말없이 풀렸다 → 먼저 경고.
- 거절 이유(시계 차이 등)를 연결 기록에 남김 (같은 이유는 한 번만).
- `test/pairing/run.sh`: 실제 ApiServer·LanPeers·HomeKey·BedServer 를 PC 에서 두 프로그램(서버 폰 / 요청 폰+가짜 침대)으로 돌려
  35가지 확인 — 짝짓기 전 거절, 화면 닫힘·거절·동시 요청·허용, 짝 뒤 조작이 침대 바이트까지 도착, 재전송·바꿔치기·옛 시각·남의 열쇠 거절, 짝 풀기.
  폰 화면(허용 창, 안내 카드)과 알림 신호(UDP) 는 이 시험 밖 — 폰에서 확인 필요.
- 짝짓기는 한 번만: 열쇠가 두 폰에 저장되고 이후 요청은 자동으로 도장을 찍는다. 다시 묻는 건 짝 풀기·앱 삭제·데이터 삭제 때뿐.

## 5.9.0 — 9099 창구 잠금 (사용자 결정: 허용 버튼 방식)

- 전: 같은 와이파이의 누구나 침대 조작·이름 변경, `/state` 로 침대 인증키까지 노출. `Access-Control-Allow-Origin: *` 때문에
  집 안 컴퓨터 브라우저로 연 웹페이지도 명령을 보낼 수 있었다.
- 후: `HomeKey`(집 열쇠·도장), `/hello`·`/pair`(허용 버튼, `App.PairReq`), 나머지는 도장 필수. 짝이 아닌 폰은 이웃 목록에도 안 나온다.
  설정 "폰 짝짓기"(짝지은 폰 / 다른 폰과 짝짓기 / 짝 풀기). 메인·첫 설정 화면에 짝짓기 안내.
- **옮겨갈 때:** 두 폰 모두 5.9.0 을 깔고 한 번 짝을 지어야 다시 서로의 침대를 조작할 수 있다. 5.8.0 이하 폰은 '옛 버전'으로 보인다.
- 저장 키 추가: `homeKey` (기존 키는 그대로).

## 5.8.0 (사용자 요청 2건)

침대 넘기기
- 침대 그림 카드 위에 ‹ 이름 › + 주인 폰 표시, 아래 ●○ 점. 카드를 옆으로 쓸거나 ‹ › 로 다음/이전 침대 (내 침대 → 이웃 침대 순, 끝에서 처음으로).
  탭 버튼도 같은 순서(`selectIndex`). 마지막으로 본 침대를 `selToken` 에 저장해 다음에 그 침대부터 (이웃 침대면 목록이 도착할 때 옮김).
- 이웃 침대를 보는 동안 이웃 상태를 1.2초마다(평소 3초) 받아와 리모컨처럼 바로 보이게.

앱을 닫으면 끄기
- 화면이 안 보이게 되면(`onStop`, 최근 앱에서 지움 `onTaskRemoved`) 5분 뒤: 이웃 창구·이웃 찾기(`App.stopNet`) + 침대 서버(서비스 `stopSelf`) 모두 끔. 알림줄에서도 사라진다.
  앱을 켜면(`onResume`) 다시 켠다 — 침대가 다시 붙는 데 몇 초. 5분은 `elapsedRealtime` 기준(폰이 잠든 시간 포함), 30초마다 확인.
- 그동안 다른 폰은 이 폰의 침대를 조작할 수 없다. 설정 "앱을 닫아도 대기"(`stayOn`, 기본 꺼짐)를 켜면 예전처럼 계속 돈다.
  `BootReceiver` 도 `stayOn` 일 때만 부팅·업데이트 뒤 서비스를 켠다. 서비스는 `stayOn` 일 때만 START_STICKY.
- 끄고 다시 켤 수 있게 `ApiServer`(자기 소켓일 때만 '꺼짐' 처리)와 `LanPeers`(켤 때마다 번호 `gen`, 받기 소켓을 닫아 깨움)를 정리.

## 5.7.0 — 배터리 (사용자 요청)

- `ServerService`: PARTIAL_WAKE_LOCK(폰이 잠들지 못함)·WifiLock(와이파이 절전 막음)을 늘 잡던 것 → 설정 "연결 유지 강화"(`keepAwake`, 기본 꺼짐)를 켰을 때만.
  꺼도 앞쪽 서비스(connectedDevice)라 도즈 중에도 네트워크는 살아 있고, 들어오는 연결·패킷이 폰을 깨운다는 가정. **폰에서 확인 전** —
  화면이 꺼진 뒤 한참 지나 침대가 반응하지 않으면 켜라고 설정 화면에 안내.
- `LanPeers`: MulticastLock(집 와이파이의 모든 방송 패킷에 폰이 깨어남)을 늘 잡던 것 → 화면이 보일 때만(`setListening`).
  알림 신호는 화면이 보일 때 4초, 뒤에서 10초. 한 번 찾은 폰은 신호가 뜸해도 10분 동안 `/state` 로 직접 확인(3번 연속 실패하면 신호 올 때까지 쉼), 목록 유지 시간 20초 → 30초.
- 되돌려야 하면: 설정 "연결 유지 강화" 켜기 = 5.6.2 까지의 WakeLock·WifiLock 동작. (MulticastLock 은 켜지지 않는다 — 뒤에 있는 폰은 남의 신호를 받을 필요가 없다)

## 5.6.2 — 최종 점검

- `BedServer` 의 핀 값 목록(LinkedHashMap)을 침대 스레드가 쓰는 동안 화면이 훑으면 `ConcurrentModificationException` →
  "연결 기록 보기"를 누른 순간 앱이 죽을 수 있었다. `/state` 응답도 가끔 실패. BedServer 는 손대지 않고 읽는 쪽에서 다시 시도.
- 새 버전 확인 결과가 화면이 닫히는 중에 오면 창을 띄우다 앱이 죽을 수 있었다 → `alive()` 확인.
- 값 묻기(askNow)를 2.5초마다 새 스레드로 — 이웃 폰이 느리면 쌓였다 → 한 번에 하나만.
- 알림 권한을 앱을 켤 때마다 물었다 → 처음 한 번만.
- 앱을 새로 켜면 무드등·스피커가 늘 '꺼짐' → 침대를 고를 때와 20초마다 V52·V61 도 묻는다.
- 알림줄이 연결돼 있어도 "침대를 기다리는 중" → "침대 N대 연결됨".
- 확인 안 한 채 남긴 것: 서버 서비스가 WakeLock·WifiLock 을 늘 잡고 있어 배터리를 쓴다. 5.1.0 에서 침대 연결 유지 때문에 넣은 것이라 폰 확인 없이 빼지 않았다.

## 5.6.1 — 앱 안 설치 멈춤 (사용자 신고)

- 증상: 5.5.0 에서 "지금 설치" → "내려받는 중…" 에서 멈추고 설치 창이 안 뜸 (갤럭시, 안드로이드 16 추정).
- 원인(추정, 폰 로그 미확인): `InstallReceiver` 가 안드로이드의 '설치' 확인 창을 **리시버에서 직접** `startActivity` 했다.
  안드로이드 14+ 는 배경 화면 띄우기 제한으로 이걸 **오류 없이 조용히** 막는다. 그리고 성공 경로에서는 화면 글자를 안 바꿔서 "내려받는 중"이 그대로 남았다.
- 수정: 리시버는 확인 창을 `App.keepConfirm` 에 맡기고 화면을 깨운다(`App.ping`) → 화면(`handleInstall`)이 띄운다.
  결과(성공·취소·실패)는 `App.installResult` 로 화면에 전달해 알림. 30초 안에 답이 없으면 멈춰 있지 않고 안내 창.
- 5.5.0·5.6.0 은 이 문제 때문에 앱 안 설치가 안 될 수 있다 → 5.6.1 은 **브라우저로 한 번 직접** 설치해야 한다.

## 5.6.0 — Codex 검수 반영

- 업데이트: 6시간 배경 확인·자동 설치를 없앴다 (사용자: 배터리). 앱을 켤 때(1시간 간격) 확인 → "설치 / 나중에".
- 이웃 침대 슬라이더를 끄는 중 그 침대가 사라지면 손을 뗄 때 **내 침대로 명령이 가던** 문제 → 끌기 시작한 침대와 다르면 보내지 않음.
- 목표값(targets)이 침대 구분 없이 남아 다른 침대의 +/- 계산에 쓰이던 문제 → 목표를 보낸 침대 인증키로 묶음.
- 보내기 실패해도 목표가 남아 다음 +/- 가 안 간 값 기준으로 계산되던 문제 → 실패하면 목표 삭제·알림.
- 명령을 따로따로 새 스레드로 보내 순서가 뒤바뀔 수 있던 문제 → 한 줄 대기열(`sendQ`).
- 이웃 침대가 사라져 선택이 바뀌어도 설정 화면이 옛 침대를 보여주던 문제.
- 알림 권한이 꺼져 있으면 설치 확인으로 갈 길이 없던 문제 → 앱을 열면 확인 창을 이어서 띄움. 버려진 설치 세션은 새 설치 전에 치움.
- 설치 허용 화면에 간 사이 앱이 정리되면 1시간 동안 다시 안 묻던 문제.
- 이웃 갱신이 겹쳐 옛 응답이 새 목록을 덮던 문제, 마법사 "바로 추가"가 이미 끊긴 침대를 등록하던 문제.
- 알림을 누르면 화면이 겹쳐 뜨던 문제(singleTop), 9099 포트 열기 실패 후 재시도 안 되던 문제, 폰 이름 변경이 다른 스레드에 안 보일 수 있던 문제.
- 보류: 마법사 진행 상태를 앱 프로세스가 정리된 뒤에도 복원하기 (화면 회전은 5.4.0에서 해결).

## 5.5.0 자동 업데이트

- 브라우저 대신 앱이 직접 APK를 받아 `PackageInstaller` 로 설치 (`Updater.java`, 결과는 `InstallReceiver.java`).
- 안드로이드 규칙상 **처음 한 번은** '이 출처 허용' + 설치 확인을 사람이 눌러야 한다. 앱이 스스로 설치한 뒤부터는
  안드로이드 12+ 에서 `USER_ACTION_NOT_REQUIRED` + `UPDATE_PACKAGES_WITHOUT_USER_ACTION` 으로 묻지 않고 설치된다 (폰에서 확인 전).
- 자동: 서버 서비스가 30분마다 조건을 보고, 6시간마다 확인, **마지막 조작 후 30분 넘게 조용할 때만** 설치 (`App.lastCmdAt`).
  설치 중 몇 초 서버가 끊기고, `MY_PACKAGE_REPLACED` 로 `BootReceiver` 가 다시 켠다.
- 받은 파일이 이 앱인지·새 버전인지 확인 후 설치. 서명이 다르면 안드로이드가 거부한다.
- 5.4.0 이하 → 5.5.0 은 한 번은 손으로 설치해야 한다 (옛 버전엔 이 기능이 없다).

## 5.4.0 수정 (사용자 신고 + 코드 점검)

사용자 신고
1. 폰 뒤로 버튼을 누르면 앱이 꺼짐 → `onBackPressed`: 설정→메인, 마법사→이전 단계, 메인→앱을 뒤로(끄지 않음). 화면 위에 ← 버튼.
2. 숫자·조절이 이상함 → 목표값을 "2도 이내면 도착"으로 바로 지우던 것 때문에 + 를 여러 번 눌러도 1도씩만 가고, 끄는 동안 0.8초마다 숫자가 덮어써졌다. 이제 보낸 **뒤에 새로 받은 값**으로만 도착을 판단(`settleTargets`, 핀별 받은 시각 `pinAt`). 값을 모를 때 + 를 누르면 0에서 계산해 침대가 내려가던 것도 막음.
   그림·숫자가 실제 각도와 안 맞음 → 원인 미확정(폰 없이 확인 불가). 설정 → 각도 맞추기(침대별 "끝까지 올렸을 때 실제 각도")로 표시만 환산. 침대에 보내는 값은 그대로.
3. 움직이는 중 "몇 도 → 몇 도" 가 안 보임 → 목표에 출발값을 같이 기록해 그림 아래·조절 칸에 표시.
4. 넘겨받은 폰에서 이름 바꾸기 등이 안 됨 → 넘겨받은 침대가 목록에 들어갈 길이 마법사 첫 화면뿐이었다. 메인 화면에도 "이 폰에 등록하기" 안내. ↗ 침대도 이름 바꾸기 가능(`/rename`). 넘겨준 쪽에 남은 침대는 "이 폰 목록에서 빼기" 안내.
5. 개발자 모드 삭제 → 설정 화면(톱니). 연결 기록 보기만 남김.

코드 점검에서 찾은 것
- 화면이 새로 뜰 때마다(뒤로가기·다크모드 전환) 이웃 창구(9099)가 새로 안 열리고, **옛 화면의 침대 목록을 붙잡은 채** 계속 돌았다 → 다른 폰에 옛 이름·옛 목록이 보임. `App.startNet` 한 번만, 목록은 저장소에서 매번 읽음.
- 재부팅 뒤 앱을 열기 전까지 다른 폰이 조작 불가 → 서비스에서도 `startNet`.
- 슬라이더를 스치기만 해도(스크롤하다가, 톡 쳐도) 침대가 움직임 → 옆으로 끌 때만 반응.
- 무드등·스피커: 침대가 값을 안 알려주면 늘 '꺼짐'으로 보여 끌 수 없었음 → 마지막으로 보낸 값을 기억.
- 이웃 침대 목록 순서가 바뀌면 고른 침대가 다른 침대로 바뀜 → 인증키로 다시 찾음. 내 침대와 같은 침대가 ↗ 로 한 번 더 보이던 것 제거.
- 이웃 폰을 거친 명령이 침대에 안 닿아도 성공으로 침 → 답의 ok 확인.
- 알림줄 아이콘이 '배터리 부족' 그림이었음 → 침대 그림.
- 마법사에서 와이파이를 고르면 입력 중이던 비밀번호가 지워짐, 화면을 돌리면 마법사가 처음으로 → 수정.

## 5.1.0 안정성 수정

1. 포그라운드 서비스 `dataSync` → `connectedDevice` — 안드로이드 15의 "하루 6시간" 강제 종료 회피. 부팅 자동 시작도 이 종류라야 허용된다.
2. 재부팅 후 자동 시작 (`BootReceiver`) — 서버를 켜둔 상태(`serverOn`)이고 침대가 등록돼 있을 때만.
3. 배터리 최적화 예외 요청 메뉴 — 자동으로 띄우지 않고, 이미 허용됐으면 숨김.
4. `WifiLock` — 화면이 꺼져도 와이파이가 잠들지 않게.
5. `MulticastLock` — 기종에 따라 이웃 폰 신호를 아예 못 받던 문제.
6. 화면이 안 보일 때 0.8초 갱신 중단 (서버는 계속 돔).

## 실수와 교훈 — 다음 사람이 반복하지 말 것

**저장 방식을 바꾸면서 옮기는 코드를 안 넣었다 (4.0.0).**
침대 여러 대를 지원하려고 저장 구조를 바꿨는데, 예전 설정을 새 구조로 옮기지 않아서 사용자의 침대 등록·와이파이 설정이 전부 사라졌다. 4.2.0에서 `migrateOld()`로 복구했다. → 저장 구조를 바꿀 땐 항상 옮기는 코드를 같이.

**빌드 스크립트를 기억으로 다시 쓰다가 옵션을 빠뜨렸다 (4.6.0~5.0.0).**
작업 공간이 한 번 초기화된 뒤 `build.sh`를 다시 만들면서 `--min-sdk-version 24 --target-sdk-version 35`를 빠뜨렸다. APK에 안드로이드 버전 표시가 없어져 아주 오래된 앱으로 취급됐다. 5.1.0에서 발견·복구. → 빌드 후 `aapt2 dump badging`으로 확인하는 습관.

**정지를 "현재 위치 다시 보내기"로 구현했다.**
화면에 있던 값이 오래된 것이라 정지를 누르면 침대가 0도로 내려갔다. 사용자: "정지를 누르면 왜 0으로 가. 거기서 멈춰야지." → 진짜 정지 핀(V41)을 찾아서 해결.

**정지 핀을 한 개씩 눌러가며 찾았다.**
사람이 "멈췄다"고 말하는 순간은 이미 다음 후보로 넘어간 뒤라 V35~37을 잘못 짚었다. → 후보를 절반씩 묶어 보내고 "멈췄나?"만 묻는 방식으로 V41 확정.

**테이블 슬라이더를 기본으로 보여줬다.**
사용자 침대엔 테이블이 없는데, 테이블 핀을 보내면 다리가 움직였다 (설명서의 연동 기능). → 침대별 설정으로 켠 경우만 보이게.

**"주소를 고정하세요"라고 잘못 안내했다 (4.4.0).**
실제 원인은 폰이 다른 공유기(다른 주소 대역) 뒤에 있는 것이었다. → 주소 앞 세 자리를 비교해 두 경우를 구분.
