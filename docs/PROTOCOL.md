# 침대 통신 규칙

버킷츠 Ma Bed 2M+ 의 제어 기판(ESP32 계열)은 **Blynk Legacy** 방식으로 통신한다.
제조사 앱(`cc.blynk.appexport.ma_bed`)은 Blynk의 화이트라벨 앱이었고, 서버는 `birkits.blynk.cc:443` 이었다.
2026년 5월 서비스 종료로 그 서버는 더 이상 쓸 수 없다.

이 문서의 내용은 제조사 APK 분석과, 실제 침대에 리모컨을 누르면서 오가는 값을 맞춰보며 알아낸 것이다.

## 1. 핵심 발견 — 서버 주소를 우리가 정할 수 있다

침대를 처음 설정할 때(설정 모드) 침대는 스스로 와이파이 공유기(AP)가 되고, 폰이 거기 붙어서 **집 와이파이 이름·비밀번호와 함께 접속할 서버 주소를 넣어준다.**
서버 주소가 펌웨어에 박혀 있는 게 아니라 설정 때 주입되므로, 우리 폰 주소를 넣으면 침대가 우리 폰으로 접속해 온다.

### 설정 모드 들어가기

- 침대 밑 컨트롤 박스의 나사 4개를 풀고, 안쪽 작은 검은 기판에서 micro-USB 단자 오른쪽의 **BOOT 버튼**을 찾는다 (케이스 바깥 아님).
- 전원이 켜진 상태로 BOOT를 **10초** 누른다. 빨간 불이 느리게 → 빠르게 깜빡이면 설정 모드.
- 폰 와이파이 목록에 `birkits-` 로 시작하는 이름이 뜬다 (비밀번호 없음, 뒤 글자는 매번 바뀐다).
- 폰의 **모바일 데이터를 꺼야** 한다. 안 그러면 폰이 인터넷 없는 와이파이를 무시하고 요청을 LTE로 보낸다.

### 설정 모드의 HTTP 주소 (침대 = 192.168.4.1)

| 요청 | 하는 일 |
|------|---------|
| `GET /board_info.json` | 기판 정보. 침대를 찾았는지 확인용 |
| `GET /wifi_scan.json` | 침대 자리에서 잡히는 와이파이 목록 (2.4GHz만) |
| `GET /config?ssid=&pass=&blynk=&host=&port=&port_ssl=` | 설정 주입. 끝나면 침대가 스스로 재시작 |

- `blynk` = 인증 토큰(32자). 앱이 침대마다 새로 만든다 (`Beds.newToken()`).
- `host` = 침대가 접속할 주소. **서버 역할을 할 폰의 집 와이파이 주소.**
- `port`, `port_ssl` = 둘 다 8080 (암호화 없이 평문으로 받는다).
- 요청은 반드시 와이파이 쪽 네트워크로 나가게 묶는다 (`Network.openConnection()`, `Net.get()`).

## 2. 통신 형식 (침대 ↔ 폰, TCP 8080)

모든 메시지 앞에 5바이트 머리가 붙는다.

```
[명령 1바이트][메시지 번호 2바이트, 큰 쪽 먼저][길이 2바이트, 큰 쪽 먼저][본문]
```

**응답(RESPONSE=0)은 예외** — 길이 자리에 본문 길이 대신 상태 코드(200 = 성공)가 들어가고 본문이 없다.

| 번호 | 이름 | 비고 |
|------|------|------|
| 0 | RESPONSE | 길이 자리 = 상태 코드 |
| 2 | LOGIN | 앱용 로그인 |
| 6 | PING | 살아있음 확인. 200으로 답한다 |
| 16 | HW_SYNC | |
| 17 | INTERNAL | `rtc` 요청이 오면 `rtc\0<유닉스초>` 로 답한다 |
| 20 | HARDWARE | 핀 읽기/쓰기 |
| **29** | **HW_LOGIN** | **이 침대는 2가 아니라 29로 로그인한다.** 본문 = 토큰. 200으로 답한다 |
| 41 | REDIRECT | 다른 서버로 옮겨가라는 명령 (써본 적 없음) |

### 핀 쓰기·읽기 (HARDWARE=20)

본문은 널 문자(`\0`)로 구분한다.

```
쓰기:  vw \0 <핀번호> \0 <값>      예) vw\011\030   → V11(상체)을 30으로
읽기:  vr \0 <핀번호>              예) vr\011       → 침대가 vw\011\0<현재값> 으로 답한다
```

침대는 스스로도 값이 바뀌면 `vw` 로 알려온다.

## 3. 핀 번호

| 핀 | 뜻 | 값 | 알아낸 방법 |
|----|----|----|-------------|
| V11 | 상체 각도 | 0~80 | 리모컨 상체 올림/내림 중 오는 값 |
| V13 | 다리 각도 | 0~45 | 리모컨 다리 올림/내림 |
| V14 | 테이블 | 0~850 | 테이블 미설치 제품에 보내면 **다리가 움직인다** (설명서의 테이블·다리 연동). 설정에서 켠 경우만 노출 |
| V41 | **정지** | 1 | 쓰기 전용. 후보를 절반씩 나눠 보내며 찾음 (사람 반응 속도 때문에 한 개씩 누르며 찾으면 V35~37을 잘못 짚는다) |
| V52 | 무드등 | 0/1 | |
| V61 | 스피커 | 0/1 | 켠 뒤 폰 블루투스에서 `XDADADZ` 에 연결 |
| V1·V2·V3 | 알람 1·2·3 시각 | Time Input (아래) | 접속 때 침대가 달라고 함(`vr 1 2 3 4`) + 원래 앱 화면. **5.10.0 에서 사용, 폰에서 확인 전** |
| V4 | 타이머 (추정) | Time Input? | 같은 묶음. 아직 안 씀 |
| V5·V6·V7 | 알람 1·2·3 켜기/끄기 | 0/1 | 접속 때 `vr 5 6 7`. 5.10.0 에서 사용 |
| V12 | 알람 때 상체 높이 | 0~80 (원래 앱 기본 50) | 접속 때 `vr 12`. 5.10.0 에서 사용 |
| V51~V55 | SMART LED (옵션 제품) — 감지 시간·켜기(V52)·모드·밝기·색 순서로 추정 | | 접속 때 `vr 51 52 53 54 55`. V52 만 확인 |
| V8, V15 | 미확인 | | 값은 오지만 뜻 모름 |

기판 정보(접속 때 `INTERNAL`): Blynk 라이브러리 0.6.1, heartbeat 10초, ESP32, 펌웨어 1.0.1 (2021-03-05 빌드), 템플릿 `35MaBed2M+`.

알려진 자세 (앱 기본값): 평평하게 0·0, 독서 80·0, 다리 올림 0·35, 무중력 30·30.

### 원래 앱 화면에서 알아낸 것 (2026-09-21, 사용자가 찾은 블로그 캡처)

원래 앱(Blynk 화이트라벨)의 "BED FRAME" 화면:
- **ALARM 1·2·3** — 각각 요일 선택 + 시작(START)·종료(STOP) 시각 (Blynk *Time Input* 위젯) + 켜기/끄기 버튼. 예: "08:30:00 AM - 08:33:00 AM · Thu"
- **알람시 상체높이** 슬라이더 (예: 50) — 알람 때 올라갈 상체 높이. 시작~종료 사이에 서서히 올리는 것으로 추정 (후기: "서서히 상체를 일으켜")
- **TIMER** + 버튼
- 슬라이더: 하체(L) · 상체(B) · 테이블(T), 자세 버튼: SLEEP · READ · LEG UP · ZERO G · A · B, MEMORY A·B 저장, STOP
- "SMART LED" 화면(옵션 제품만): SENSING TIME, 켜기/끄기, 모드 4개, 밝기, 색(RGB), SPEAKER 켜기/끄기

**추정:** Time Input 위젯은 설정값을 기판에 넘기기만 하고, 알람은 **기판이 스스로** 시계(`rtc` 요청으로 받는 시각)를 보고 실행한다.
그렇다면 알람 핀과 값 형식만 알면 폰이 꺼져 있어도 침대가 알람을 울린다.
Blynk Legacy 의 Time Input 값 형식(알려진 것): `vw \0 <핀> \0 <시작초> \0 <종료초> \0 <시간대 이름> \0 <요일 1=월…7=일, 쉼표> \0 <시간대 오프셋초>`.
5.9.3 에서 동기화 요청(HW_SYNC=16) 내용을 기록해 보니 침대가 `vr 1 2 3 4` · `vr 5 6 7` · `vr 12` · `vr 51~55` · `vr 61` 을 달라고 했다 → 위 핀 표.
원래는 제조사 서버가 저장했다가 이때 보내줬다. 이제는 폰이 침대가 붙을 때마다 알람 설정을 넣어준다 (`Alarms.push`).

**기판 시계:** 폰은 `rtc` 요청에 UTC 유닉스 초를 답한다(BedServer). 기판이 이 값을 한국 시각으로 쓰는지(시간대 오프셋을 더함), UTC 로 쓰는지 모른다.
그래서 처음 한 번 **알람 시험**: 알람1 = 한국 시각 기준 2분 뒤(시간대 Asia/Seoul, 오프셋 32400), 알람2 = UTC 기준 4분 뒤(시간대 UTC, 오프셋 0)로 넣고
상체(V11)가 몇 분에 오르는지로 `local`/`utc` 를 정한다. 반응이 없으면 `none` — 그때는 폰이 알람을 맡는 방식으로 가야 한다.
`utc` 면 사용자 알람을 UTC 로 바꿔 보낸다(날짜가 넘어가면 요일도 하루 옮김).

## 4. 동작 특성

- **움직이는 동안에는 `vr`(값 요청)에 답하지 않는다.** 멈춘 뒤에야 최종값이 온다. 그래서 앱은 "가는 중"을 목표값으로 따로 표시한다.
- 명령이 반 박자 늦게 먹고, 멈칫거리는 건 침대 쪽 특성이다.
- 침대 와이파이는 **2.4GHz 전용**. 5GHz 이름은 목록에 아예 안 나온다.
- 같은 토큰으로 새로 접속하면 이전 연결은 버려야 한다. 안 그러면 죽은 연결의 옛 값(예: 40도)이 화면에 남는다 (`BedServer` 가 같은 토큰을 쫓아낸다).
- 침대는 **스스로 접속해 오는 쪽**이다. 폰 주소가 바뀌거나, 폰이 다른 주소 대역(다른 공유기 뒤)에 있으면 침대는 폰을 찾지 못한다.

## 5. 폰끼리 (같은 와이파이)

침대마다 "주인 폰" 하나가 서버 역할을 한다. 다른 폰은 주인 폰을 거쳐 조작한다.

- **UDP 9098** 브로드캐스트: `MABED2|<폰ID>|<집표식>|<폰이름>` (5.9.0부터. 이전은 `MABED|<폰ID>|<폰이름>` — 받으면 '옛 버전'으로 표시).
  화면이 보일 때 4초, 뒤에서 10초마다. 받는 쪽은 화면이 보일 때만 `MulticastLock`.
  `집표식` = SHA-256("mabed-home|" + 집열쇠) 앞 12글자. 같은 표식이면 짝.
- **HTTP 9099** (5.9.0부터 **짝지은 폰만**):
  - **짝짓기** — 집 열쇠(무작위 32바이트, hex)를 나눠 갖는다.
    - `GET /hello` (누구나) → `{"phone":이름, "home":집표식}`. 침대 정보는 없다.
    - `GET /pair?name=<요청 폰 이름>` (누구나) → 받은 폰 **화면이 열려 있을 때만** '허용/거절' 창을 띄우고 최대 60초 기다린다.
      허용 → `{"ok":true,"key":<집열쇠>,"phone":이름}` (열쇠가 없으면 이때 만든다). 요청 폰은 받은 열쇠를 저장(원래 열쇠는 버림).
      한 번에 하나, 거절 뒤 10초는 새 요청 안 받음. 열쇠가 오가는 건 이 순간 한 번뿐 (평문 — 집 와이파이 암호화에 기댄다).
  - **도장** — 아래 요청은 모두 `...&ts=<ms>&sig=<hex>` 를 끝에 붙인다. `sig` = HMAC-SHA256(집열쇠, `&sig=` 앞의 경로+주소 전체, 인코딩된 그대로).
    받는 쪽: 도장 확인 → `ts` 가 ±2분 안 → 같은 `sig` 를 4분 안에 다시 쓰면 거절(녹화 재전송 막기).
    실패하면 `{"ok":false,"auth":false,"msg":이유}`. 집 안 주소(`Net.isLan`)가 아닌 곳에서 온 요청은 모두 거절.
  - `GET /state` → 폰 이름, 그 폰에 붙은 침대들(이름·인증키·online)과 핀 값, `age` = 핀 값을 받은 지 몇 ms (5.4.0부터, 폰끼리 시계가 달라 나이로).
  - `GET /cmd?token=&pin=&val=` → 그 침대에 명령. `val=read` 이면 `vr` 을 보낸다. 답 `{"ok":false}` = 침대가 안 붙어 있음.
  - `GET /rename?token=&name=` → 주인 폰에 저장된 침대 이름을 바꾼다 (5.4.0부터).
  - 응답에 `Access-Control-Allow-Origin` 을 붙이지 않는다 (5.9.0 — 집 안 브라우저로 연 웹페이지가 명령을 보내는 것 막기).
- 남은 한계: 침대↔폰 8080 은 펌웨어가 정한 방식이라 잠글 수 없다. 인증키를 아는 사람은 가짜 침대로 접속해 진짜 연결을 끊을 수 있다.
  5.9.0부터 인증키는 짝지은 폰에게만 알려주므로 새어 나갈 길은 크게 줄었다.

## 6. 안드로이드 쪽 함정

- 폰 주소를 구할 때 `192.0.0.4` 가 잡힐 수 있다 — 이동통신사 IPv6 변환용 가짜 주소(464XLAT). 이걸 침대에 넣으면 영영 못 붙는다. `Net.isLan()` 이 걸러낸다 (`192.0.0.`, `169.254.` 제외, `wlan`/`ap` 인터페이스만).
- 와이파이 이름을 읽으려면 **위치 권한**이 있어야 한다. 저장된 와이파이 **비밀번호는 안드로이드가 절대 알려주지 않는다** — 사용자가 한 번은 입력해야 한다.
